Testing a trading strategy

Open the Strategy Tester from the toolbar to see how a strategy would have traded the active chart's symbol and timeframe. Pick a built-in strategy, change its rules in plain sentences ("Buy when EMA 9 crosses above EMA 21"), or write your own in TypeScript. The tester re-runs as you change anything and shows the trades on the chart, an equity curve, performance figures and a list of trades.

Under Settings you choose the starting capital, order size, commission, slippage, trade direction, an optional stop loss and take profit, and how many of the latest bars to test (up to 5,000; the chart loads more history when needed). Save… keeps a strategy under My strategies.

How trades are simulated

  • A signal on a bar is acted on at the next bar's open, so a strategy never trades on a price it couldn't have known.
  • Stop loss and take profit are checked inside every bar against its high and low. If one bar reaches both, the tester assumes the stop came first (the cautious guess). If a bar opens past a level, the fill is at the open.
  • A buy signal while short (or a sell-short signal while long) closes the position. When Trade direction is "Both" it also opens the other side.
  • Commission is charged on both sides as a percent of the trade's value. Slippage makes each fill that percent worse.
  • A position still open at the last bar shows as the open trade. It counts in the equity curve, not in the trade figures.
  • During bar replay only the bars up to the replay time are tested.

Writing your own

Open the strategy menu in the tester, pick New strategy in code, then click Edit code. A strategy file looks like this:

export default strategy({
  name: "EMA Cross with RSI filter",
  description: "Buy when the fast EMA crosses above the slow one, unless RSI is overbought.",
  params: {
    fast: input.length(9, "Fast EMA"),
    slow: input.length(21, "Slow EMA"),
    maxRsi: input.float(70, "Skip buys above RSI", { min: 1, max: 100 }),
  },
  run(bars, params, ta) {
    const close = ta.source(bars, "close");
    const fast = ta.ema(close, params.fast);
    const slow = ta.ema(close, params.slow);
    const rsi = ta.rsi(close, 14);
    const up = ta.crossover(fast, slow);
    const down = ta.crossunder(fast, slow);
    return {
      enterLong: up.map((cross, i) => cross && (rsi[i] ?? 0) < params.maxRsi),
      exitLong: down,
      enterShort: down,
      exitShort: up,
    };
  },
});

run gets the chart's candles ({ time, open, high, low, close, volume }, oldest first), the current params, and ta, the same building blocks custom indicators use (see custom-indicators.md). It returns one true/false per bar for any of enterLong, exitLong, enterShort and exitShort. Missing lists mean "never", numbers count as true when they aren't 0, and anything else counts as false.

params take the same input helpers as indicators: length, int, float, source, select, bool. They show up as settings in the tester.

Strategies run in the same sandbox as custom indicators: they only see the candles, never your settings, keys, files or the internet. One that runs longer than 5 seconds is stopped.
