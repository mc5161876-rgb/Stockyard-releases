Control Stockyard with AI agents

AI apps such as Claude Desktop and Claude Code can work in Stockyard for you. They can open charts, read prices, draw, add indicators, set alerts, change layouts and themes, and save workspaces. Scripts can do the same through a small local API.

Stockyard only reads market data. Agents can't place trades, and they never see your Alpaca, Tradier or X keys.

To chat with an AI inside Stockyard instead, use the assistant. It runs the same commands with your own Anthropic or OpenAI key, or a free local model.

Turn agents on

  1. Open Settings (gear icon or ⌘,) and choose Agents.
  2. Pick an access level:
Level What agents can do
Off (default) Nothing. The local server is stopped.
Read only Look at charts, prices, drawings, alerts and settings. Every change is refused with a message that tells the agent to ask you.
Ask before acting Look freely. Each change shows a prompt with the agent's name and what it wants to do. Press Allow or Deny. Prompts come one at a time, and a prompt nobody answers is denied after 2 minutes.
Full control Change anything without asking.

Only you can change the access level. No agent command can read or change it.

The server listens on 127.0.0.1 only, so other computers can't reach it. Web pages in a browser can't reach it either.

Connect Claude Desktop

  1. In Settings → Agents, press Connect Claude Desktop. Stockyard adds itself to Claude Desktop's claude_desktop_config.json and keeps a .bak copy of the old file.
  2. Quit Claude Desktop completely and open it again.

Stockyard now shows in Claude's tools. Stockyard must be open, with agents on, while Claude uses it.

To add it by hand, put this in claude_desktop_config.json, using the path that Settings → Agents shows:

{
	"mcpServers": {
		"stockyard": { "command": "/Applications/Stockyard.app/Contents/MacOS/Stockyard", "args": ["mcp"] }
	}
}

On Windows, command is the path to Stockyard.exe, with each backslash doubled.

Connect Claude Code

Run the command that Settings → Agents shows, for example:

claude mcp add stockyard -- "/Applications/Stockyard.app/Contents/MacOS/Stockyard" mcp

Any other MCP client works the same way: run the Stockyard program with the argument mcp. It speaks MCP over stdin and stdout and passes each message to the open app. It never opens a window.

Use the HTTP API from scripts

Settings → Agents shows the address (for example http://127.0.0.1:47821) and a token. The address and token are also in agent.json:

  • macOS: ~/Library/Application Support/app.opencharts.desktop/agent.json
  • Windows: %APPDATA%\app.opencharts.desktop\agent.json
  • Linux: ~/.local/share/app.opencharts.desktop/agent.json

Send the token as a bearer token. Requests with an Origin header are refused.

TOKEN=...   # from Settings → Agents
curl -s http://127.0.0.1:47821/v1/commands -H "Authorization: Bearer $TOKEN"

curl -s -X POST http://127.0.0.1:47821/v1/commands/open_symbol \
	-H "Authorization: Bearer $TOKEN" -d '{"symbol": "ETH-USD"}'

curl -s -X POST http://127.0.0.1:47821/v1/commands/add_drawing \
	-H "Authorization: Bearer $TOKEN" \
	-d '{"tool": "hline", "points": [{"time": 1763856000, "price": 3400}], "text": "support"}'

Each call returns {"ok": true, "result": ...} or {"ok": false, "error": "..."}.

Status Meaning
200 Done.
400 The arguments are wrong. The error says which field and why.
401, 403 Bad token, or the access level doesn't allow this command.
404 No such command.
500 The command failed, for example because a data source was unreachable.
504 Nobody answered an approval prompt in time, or the app is busy.

Press New token in Settings → Agents if the token leaks. Scripts that use the old token stop working.

The API runs at the access level you picked. Under Ask before acting, a call that changes something waits until you answer the prompt.

From a terminal

The Stockyard program also has a command line mode that reads agent.json for you:

Stockyard cli list
Stockyard cli get_app_state
Stockyard cli set_timeframe '{"timeframe": "4h"}'

It prints the JSON result and exits with 0 on success and 1 on failure. Calls from it show as Command line in the activity list.

MCP over HTTP

POST /mcp speaks MCP (Streamable HTTP, JSON responses only, protocol 2025-06-18, older versions accepted). initialize returns an Mcp-Session-Id header. A session id the app doesn't know, for example after Stockyard restarted, gets a 404 so the client starts a new session.

See what agents did

Settings → Agents → What agents did lists every call: the time, the agent, what it asked for, and whether it was done, refused or failed. Clear empties the list. The app keeps the last 500 calls. Agents can read the same list with get_agent_log.

Tips for agents and prompt writers

  • Call get_app_state first. It lists the charts, numbered from 0, and each chart's indicators with ids.
  • Commands that take chart use the active chart when you leave it out.
  • Symbols look like BTC-USD for crypto and tradier:AAPL for stocks. search_symbols finds them. A bare ticker such as AAPL or ETH is looked up.
  • Times are Unix seconds (UTC), the same as bar times from get_bars.
  • Drawings belong to a symbol and show on every timeframe. list_drawing_tools says how many points each tool takes. The user can undo an agent's drawing with ⌘Z or Ctrl+Z.
  • get_chart_snapshot returns a PNG of the chart with the numbers behind it. Drawings and alert lines are a separate layer, so they are listed as data and are not in the picture.

Add a command

All commands live in one table, COMMANDS in src/agent/commands.ts, built from the files in src/agent/commands/. Each entry has a name, a description written for a language model, an access kind (read or act), an input schema made with s from src/agent/schema.ts, a one-line summary for the approval prompt, and a run function that calls the same stores as the UI. The schema gives MCP clients a JSON Schema and parses the arguments before run sees them.

A new feature adds a file in src/agent/commands/ and spreads its commands into COMMANDS. MCP, the HTTP API, the command line and the permission checks then cover it with no other change. Add a row to the table above too, and map the feature in src/agent/coverage.ts: a test fails when a command-bar command, a Settings page or a setting has no agent command and no reason it stays with the user. Testing has the steps.

The desktop side of the bridge (the local server, the mcp and cli modes, and Claude Desktop setup) is described in agents-contract.md.
