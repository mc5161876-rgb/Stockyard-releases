Contributing

Stockyard is a Tauri desktop app. The window is a React and TypeScript web app, and a small Rust backend holds API keys and the Tradier and Alpaca streams. Charts are drawn with TradingView Lightweight Charts.

Set up your computer

Install these once:

  1. Node.js 22 from nodejs.org.
  2. Rust from rustup.rs.
  3. Platform build tools:
    • Mac: run xcode-select --install in Terminal.
    • Windows: install Microsoft C++ Build Tools with Desktop development with C++.

Then, in the repository folder:

npm install
npm run app

The first npm run app compiles the Rust shell and takes a few minutes. Later launches take seconds.

Commands

Command What it does
npm run app Desktop app with hot reload
npm run dev Web UI only, at http://localhost:1420. Crypto works here. US stocks need the desktop app.
npm test Unit tests (Vitest)
npm run e2e End-to-end tests: the real app in a browser, against a fake market and a fake desktop backend (Playwright)
npm run typecheck TypeScript checks
npm run docs Build this docs site into site/
npm run app:build Build an installer for your computer

How the code is laid out

Folder What lives there
src/data/ Market data. types.ts holds the MarketDataAdapter interface, the only data type the UI imports. coinbase/ serves crypto. US stocks go through StocksAdapter.ts, which serves them from tradier/ or alpaca/.
src/chart/ The Lightweight Charts wrapper, live bars, chart settings, and the right-click menu.
src/indicators/ Indicator math as pure functions (ta.ts), the built-in library, stacks, the shop, and custom indicators.
src/drawings/ Drawing tools: pure geometry, a per-symbol store with undo, the SVG layer, and the tool rail.
src/layout/ Multi-chart layouts, chart linking, and workspaces.
src/alerts/ The alert engine, its store, notifications, and the alert manager.
src/replay/ Bar replay.
src/watchlist/ The watchlist panel.
src/options/ The options chain panel, and its chain logic in chain.ts.
src/themes/, src/settings/themes.ts Themes as data, and animated backgrounds.
src/widgets/, src/plugins/ Floating widgets and the plugin API.
src/onboarding/ The first-run tour. Steps live in steps.ts and point at data-tour attributes.
src/settings/ The settings store. Every UI choice is a named, saved setting.
src-tauri/ The Rust backend. src/tradier.rs and src/alpaca.rs own each provider's keys, rate limits, and stream.
docs/ This site. Each .md file is one page.

Rules the code follows

  • Every UI choice is a setting. Add a named key to src/settings/store.ts instead of hard-coding a look or layout.
  • Keys never reach the web view. The Rust backend reads secrets from the OS keychain. Do not pass a key to the front end, a plugin, an indicator, or an agent tool.
  • Read-only. Stockyard never places orders. Do not add calls to order or account endpoints.
  • The UI never imports a provider. Charts talk to MarketDataAdapter only.

Add common things

  • An indicator: add an entry to src/indicators/library.ts, built from the helpers in ta.ts. It appears in the shop, quick add, stacks, and the settings dialog.
  • A data provider: implement MarketDataAdapter from src/data/types.ts and register it in src/data/registry.ts. Its symbols get a prefix, such as tradier:AAPL, so tickers never collide.
  • A tour step: add a row to TOUR_STEPS in src/onboarding/steps.ts, and put a matching data-tour attribute on the element. A test fails if a step points at an attribute that no longer exists.
  • Agent commands for a feature: add them in src/agent/commands/ and map the feature in src/agent/coverage.ts. Testing has the steps.
  • A docs page: add a .md file to docs/, then add it to the PAGES list in scripts/build-docs.mjs.

Tests and checks

Each pull request runs typecheck, unit tests, a web build, end-to-end tests and a Rust check. The unit tests also build this docs site and fail on a broken link. Run the same checks before you push:

npm run typecheck && npm test && npm run e2e

Test behavior a user can see, not internal details. Testing shows how to add a test for your feature.

Releases

  1. Bump the version in src-tauri/tauri.conf.json, package.json, and src-tauri/Cargo.toml.
  2. Merge to main.
  3. Run Actions → Release → Run workflow.

The workflow builds a Mac .dmg and a Windows installer, signs the update, and publishes it to the public Stockyard releases repository. Installed apps pick it up on their next launch.

The docs site publishes itself when a change to docs/ reaches main.
