Community library

The Community window in Stockyard lists themes, indicators, indicator stacks, workspaces, and plugins that people shared. You open it from the Community button at the top of the window. Installing an item needs no account and no token.

Where the library lives

The source is community/items/ in this repository. Each item is two files in community/items/<kind>/:

  • <id>.json is the listing: id, kind, name, description, author, version, tags, and an optional minAppVersion.
  • <id>.<kind>.<ext> is the file that Stockyard installs, such as fjord.theme.json or big-movers.plugin.js.

scripts/build-community.mjs checks every item and writes community/dist/. The output has index.json, the files, the README, and the submission issue form. index.json adds a file path, a sha256, and an updatedAt date to each listing.

The Community library workflow (.github/workflows/community.yml) runs on each push to main that changes the library. It builds community/dist/ and pushes the result to the public mc5161876-rgb/Stockyard-community repository with the RELEASES_TOKEN secret. On the first run, it creates that repository. The app reads https://raw.githubusercontent.com/mc5161876-rgb/Stockyard-community/main/index.json.

community/README.md is also the public repository's README. It explains how to submit an item and how maintainers add one.

How an install stays safe

  1. The app downloads the item's file from the same repository as the index.
  2. The app hashes the bytes with SHA-256. If the hash differs from the one in the index, the app refuses the file and changes nothing.
  3. The kind's own importer reads the file. Themes go through importThemeCode, stacks through importStack, and workspaces through importWorkspace. Each importer drops anything it does not recognize.
  4. Indicators are checked and run in the indicator sandbox. See custom-indicators.md.
  5. Plugins run with full access to the app. The app shows a confirm step that says so and can show the code. The plugin installs only after the user clicks Install plugin.

The app records each installed item's id and version in settings.hubInstalled. When the library lists a different version, the item's button changes to Update. An update runs the install again and replaces the old copy.

Each kind's label, trust level, installer, and share text live in one table, KINDS in src/community/kinds.ts.

How sharing works

Community → Share lists the user's own themes, indicators, stacks, workspaces, and plugins. Share copies the item to the clipboard and opens the library's submission form on GitHub, filled in. If the link would be longer than 7000 characters, the form opens without the content, and the user pastes it from the clipboard.

Try the library locally

  1. Run node scripts/build-community.mjs --serve. It builds community/dist/ and serves it on http://localhost:1421/.
  2. In another terminal, run VITE_COMMUNITY_BASE=http://localhost:1421/ npm run dev.
  3. Open http://localhost:1420/ and click Community.

VITE_COMMUNITY_BASE works only in the browser preview. The desktop app can reach only the hosts in src-tauri/capabilities/default.json.
