Testing

Every feature ships with tests. Two kinds, both run on every pull request.

Kind Where Run locally What it checks
Unit tests/*.test.ts (Vitest) npm test Pure logic: indicator math, alert conditions, drawing geometry, layouts, parsing.
End to end e2e/*.spec.ts (Playwright) npm run e2e The real app in a real browser: click, type, reload, and see the result on screen.

CI (.github/workflows/ci.yml) runs typecheck, unit tests, the build, the end-to-end suite and cargo check. Merge a pull request only when every check is green.

The fake market

End-to-end tests never touch the internet. e2e/fixtures.ts fakes Coinbase:

  • REST (/products, /candles, /stats) answers with the same smooth price wave every run.
  • The WebSocket accepts subscriptions; await market.trade("BTC-USD", 71000) pushes a live trade, so a test can move the price.
  • Every other outside host is blocked.

Use the app fixture to get the page already loaded with the welcome guide dismissed. Use page plus market to test first launch.

The fake desktop

US stocks, options and saved keys only work in the desktop app. test.use({ desktop: { tradier: true, alpaca: true } }) runs the app as if it were the desktop app, with a fake backend (e2e/desktop.ts):

  • The tradier_* and alpaca_* commands answer like Tradier's and Alpaca's APIs: quotes, history, option expirations and chains with greeks. AAPL trades at 230.60, so 230 is the strike at the money.
  • The keys you name start out saved, desktop: {} starts with none, and keys saved in Settings survive app.reload(). The fake accepts Alpaca key IDs that start with PK.
  • assistant_send answers like Anthropic's Messages API, from a scripted model. Ask it for a 4 hour chart and it calls set_timeframe. A message with "wait" takes a minute, so a test can press Stop. desktop: { anthropic: true } starts with an Anthropic key saved, and window.__assistantRequests holds every request the app sent.
  • Other desktop commands (sync, news keys, the updater) answer as if nothing were set up, and Coinbase still comes from the fake market.

Adding a test for your feature

  1. Unit-test the logic in tests/<feature>.test.ts. Keep logic in plain .ts modules so it is testable without React.

  2. Add e2e/<feature>.spec.ts for the main user flow:

    import { test, expect } from "./fixtures";

test("a live trade updates the watchlist and a click opens the chart", async ({ app, market }) => {
  await market.trade("SOL-USD", 155.55);
  await expect(app.getByText("155.55").first()).toBeVisible();
  await app.getByText("SOL", { exact: true }).click();
  await expect(app.getByText("SOL/USD · 1h · Coinbase")).toBeVisible();
});

  3. Assert what a user sees: text, titles, roles, a value that survives app.reload(). Find elements by getByTitle, getByRole, getByLabel or getByPlaceholder. When nothing visible identifies an element (an SVG shape, a canvas overlay), add data-testid.

  4. Never add waitForTimeout to wait for the app. Wait on what the user would see with expect(...). If the app needs time to start listening (like an alert loading history), retry the action inside expect(async () => { ... }).toPass().

  5. Run npx playwright test --repeat-each=5 e2e/<feature>.spec.ts before pushing. A test that fails once in five is a bug in the test or the app, not noise.

Adding a feature? Add its agent commands

AI agents use the whole app through the commands in src/agent/commands/ (Control Stockyard with AI agents). A feature isn't done until an agent can do what its UI does.

  1. Put the feature's actions in plain .ts functions that the UI and the agent command both call, so they can't drift apart.
  2. Add the commands, with a row each in the table in docs/agents.md, and test them through call() from tests/agentHelpers.ts.
  3. Map the feature in src/agent/coverage.ts. A new command-bar command or Settings page doesn't compile until it has a row there. A new setting that update_settings can't write fails tests/agentCoverage.test.ts until it has one.
  4. Something only a person can do, like picking a file or entering a key, gets { uiOnly: "<why>" } in place of commands.

Debugging a failure

CI uploads e2e-report (screenshots and traces) when the suite fails. Locally, npx playwright test --trace on then npx playwright show-trace test-results/<test>/trace.zip.
